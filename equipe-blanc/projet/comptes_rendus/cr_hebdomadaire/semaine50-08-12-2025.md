# Bilan hebdomadaire – Semaine 48 (24/11/2025 – 28/11/2025) – Configuration réseau et services

Cette semaine, j’ai finalisé la configuration du réseau en attribuant toutes les adresses IP nécessaires pour assurer la communication entre les différentes organisations et le FAI. Les routes ont été configurées sur la DMZ et le pare-feu, ce qui m’a permis, après plusieurs tests, de joindre à la fois le FAI et l’équipe verte.

J’ai également mis en place le service DHCP et le Dynamic DNS. Une zone blanc.iut publique et blanc.iut.priv privée a été créée, autorisant uniquement les machines du réseau privé à interroger cette zone. Ce choix a été motivé par la nécessité d’installer un client NFS sur chaque machine utilisateur du réseau privé. En utilisant Ansible, chaque machine lancée via le Vagrantfile reçoit une adresse statique, mais ce sont les enregistrements FQDN déclarés dans le playbook Ansible qui feront référence à leur adresse IP. Ainsi, lorsque le serveur DHCP attribue une nouvelle adresse à une machine, il l’inscrit automatiquement dans la zone DNS privée. Ansible peut alors récupérer l’adresse IP directement via le nom de domaine, offrant une grande flexibilité pour la gestion des machines.

Une paire de clés SSH a été générée pour la machine Ansible. La clé publique a été déployée dans le dossier ~/.ssh/authorized_keys de chaque machine utilisateur lors du provisionnement, facilitant les accès automatisés.

Concernant le serveur DHCP, chaque service dispose d’une adresse IP statique qui ne changera pas. Le serveur DHCP attribuera donc uniquement des adresses dans une plage prédéfinie.

Les règles du pare-feu ont été configurées afin :

D’autoriser la communication entre la DMZ et le réseau privé,

De bloquer les connexions entrantes et sortantes entre le réseau privé et Internet,

D’autoriser la communication entre la DMZ et Internet.

J'ai mis en place les routes sur le pare-feu, sur ma DMZ, et le routeur avec la configuration attribuée par le FAI.
